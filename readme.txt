A custom Gutenberg block that displays a responsive, configurable grid of your site's most recent posts.

== Description ==

Recent Posts Grid is a small, focused custom block built to demonstrate a complete modern block-development workflow:

* `block.json` metadata (API version 3) as the single source of truth for both the editor and PHP registration.
* A dynamic block: rendering happens entirely in `render.php` via `WP_Query`, so the block always reflects live content and respects the site's own template/theme styling hooks.
* A real editing experience — `InspectorControls` panels for post count, columns, category, order, and which fields to display (thumbnail, excerpt, date, author) — backed by `ServerSideRender` so the editor preview is pixel-identical to the front end.
* Block Supports for wide/full alignment and color (background, text, link), so it plays nicely with block themes and Global Styles.
* Editor category data pulled live via `@wordpress/core-data`, rather than hard-coded.

Use it as-is, or as a starting point for a similar dynamic block.

== Installation ==

1. Upload the plugin folder to `/wp-content/plugins/`, or install the zip via **Plugins → Add New → Upload Plugin**.
2. Activate the plugin through the **Plugins** screen.
3. Add the **Recent Posts Grid** block from the block inserter (search "Recent Posts Grid" or look under the Widgets category).

== Frequently Asked Questions ==

= Does this work with Classic themes as well as block themes? =

Yes. The block only relies on core WordPress APIs (`WP_Query`, block supports), so it works in any theme that supports the block editor.

= Why is there no `save()` function in the block's JavaScript? =

This is a *dynamic* block — its markup is generated by PHP (`render.php`) on every request, not saved into post content. This keeps the front-end output in sync with live data (new posts, edited titles, etc.) without ever needing a "block validation" / re-save step after a plugin update.
